# 3.4.0-apolox plan: everything up to date

**Status: plan, not started.** Comes after 3.3.1 (which collects small fixes first). The detailed steps, gates and smoke test
are in [dependency-upgrade-plan.md](dependency-upgrade-plan.md); this file is the release plan on top of it: target versions,
order, what each step touches, and how to ship it safely.

Checked on 2026-11-19 with `npm outdated` and `npm audit`: 47 direct packages are a major version behind; `npm audit` reports
88 advisories (high 41, moderate 41, low 6, critical 0), almost all in Angular 16, Electron 38, jimp and the build tools.

## Goal

- Every direct dependency on its latest major (or the newest one that works, written down with the reason).
- `npm audit --omit=dev`: no critical or high advisories in what ships in the app.
- The app keeps working the same: library, CUE albums, gapless, equalizer, fades, statistics, Discord, all three platforms.
- Old leftovers removed (unused packages, deprecated tools).

## Order (each step: its own branch, PR, and test build)

The rule from the upgrade plan stays: one major at a time, all gates green before the next step.

1. **Clean-up (small, medium effort)**
   - Remove `tslint`, `core-js` (if unused), `node-fetch` (if `fetch` works), check `wait-on` and `electron-reload`.
   - The plain-text artist biography fix (the "Urgent" item of the upgrade plan), before anything else.
   - In-range updates: `electron-builder`, `ts-jest`, `fs-extra`, `@electron/remote` 2.1.4, `sanitize-filename`.
2. **Electron 38 → 45**, one major per step, with `better-sqlite3` rebuilt each time and `@types/node` following
   Electron's Node. Done before Angular, because Angular's newer build tools need a newer Node and Chromium anyway.
   At 13: `better-sqlite3` 13. At the end: `electron-log` 5.
3. **Angular 16 → 22**, one major per step. Each step updates Angular, the CLI, Material, CDK, `@angular-eslint`,
   `@angular-builders/custom-webpack`, `jest-preset-angular`, TypeScript and zone.js together.
   - 16 → 17: RxJS 7 (`toPromise()` × 22), new control flow is optional (keep `*ngIf` for now).
   - 17 → 18 → 19: Material 3 theming becomes the default; theme files (`src/styles`, the accent colour code) need work.
   - 19 → 20 → 21 → 22: follow update.angular.dev; `angular-split` and `@ngx-translate` to the versions that match.
4. **Test and lint tools**: Jest 30, ESLint flat config (new lint baseline), Prettier.
5. **Images and parsers**: node-vibrant 4, jimp, fast-xml-parser 5, node-html-parser 9, cheerio 1.2, uuid 14, icon fonts.
6. **Release 3.4.0**: change log, full smoke test on Linux, Windows and macOS builds from CI, then the release workflow.

## Gates for every step

- `npm run test` and `npm run test-database-integration` (both run in CI now).
- `scripts/dev/try-fix.sh` (install, tests, production build, lint baseline, advisory check).
- `node scripts/dev/eq-harness/run.js` and `node scripts/dev/playback-harness/run.js` (equalizer, fades, CUE playback).
- `scripts/dev/app-screenshots.js` before and after each Angular and Material step: every page and dialog side by side.
- The manual smoke test in the upgrade plan, on an installed build, with a **copy** of the real database.

## Risks and how to handle them

| Risk | Where | How |
| --- | --- | --- |
| The look changes (Material 3) | Every page and dialog | Screenshots before and after; theme variables kept; fix per page |
| Audio changes with a new Chromium | Players, gapless, crossfade, equalizer, fades, `dopamine-audio://` | Harnesses after every Electron step; listen to a CUE album and a fade |
| Native module does not build | `better-sqlite3`, `discord-rpc` | Rebuild per step; CI builds all platforms |
| Database | Migrations stay the same; no schema change planned | Copy of `Dopamine.db` (+ `-wal`, `-shm`) before every test build |
| Too many changes at once | Everything | One branch per step; any step can be dropped without losing the others |
| Usage budget | All of it is high-effort work | Spread over several sessions; one step per session is fine |

## Features after the upgrade

Once everything is current, 3.4 adds (see `feature-ideas.md` for details): a Navidrome/Subsonic client, bit-perfect
output on Linux with optional EQ, and MusicBrainz auto-tagging with a batch tag editor and file organiser.

## Out of scope for 3.4.0 (later)

- Full Electron hardening (`contextIsolation`, preload, removing `@electron/remote`): a large refactor of its own,
  better as 3.5.0 once everything is current. Only the biography fix and a Content Security Policy go into 3.4.0.
  3.5 then adds the features that open the app to the network or devices: phone remote, CD ripping, casting and sync.
- Zoneless Angular and the new control flow syntax: optional modernisation, not needed to be up to date.

## Effort

About 15–25 high-effort sessions in total: Electron 7 steps (usually quick each), Angular 6 steps (the biggest part, mostly
16 → 17 and the Material 3 steps), tools and parsers a few more. Claude can build and test everything on Linux and in CI; testing
the installed app on Windows and macOS, and listening, is the owner's part.
